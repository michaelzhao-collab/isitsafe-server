# IsItSafe / StarLens AI — V5.1 需求文档：家庭 IM 互动（家庭守护闭环）

> **版本**: V5.1 Draft v1
> **日期**: 2026-07-08
> **状态**: 已过口头评审，待排期
> **承接**: V5 需求文档（市场战略期）§2.1 主线 —— 家庭 + 老人守护。本期解决核心问题：**家庭功能太单一，加入后无事可干，没有互动就没有长留**。
> **核心决策（已定）**:
> 1. 家庭互动底座用**第三方 IM 服务商**（不自建），所有系统内容以**卡片消息**流进同一条家庭群聊；
> 2. **家庭创建人 = 群主**，兑换邀请码加入家庭 = 自动入群，家庭与群生命周期完全同步；
> 3. 审核不建团队，但**举报 + 拉黑必须做**（App Store Guideline 1.2 过审门票）；
> 4. **结构化事件数据必须落自己的库**（family_event），IM 只承载会话；
> 5. 老人端交互第一优先级：语音输入、单按钮卡片、快捷回复 chips，**位置精细设计**。

## 1. 目标与北极星

| 问题 | 本期答案 |
|---|---|

## 3. IM 服务商选型

### 3.1 对比（2026-07 报价口径）

| 服务商 | 海内外覆盖 | 免费档 | 超量价格 | 内容安全 | 结论 |
|---|---|---|---|---|---|
| **腾讯云 Chat（国际版 Tencent RTC Chat）** | ✅ 全球节点，国内可用 | **1,000 MAU 永久免费**，无并发限制 | ~$0.015/MAU/月 | 有安全插件（按量） | ✅ **推荐** |
| 腾讯云 IM（国内站） | 国内强，海外一般 | 体验版免费；专业版赠 1 万 DAU | 超量 1000 元/万 DAU/月 | 有 | 备选（若国内外分开部署） |
| 融云 / 环信 | 国内强，海外覆盖弱 | 有开发免费档 | 数百-上千元/月起 | 有 | 海外覆盖不满足 |
| Sendbird / Stream | 海外强，国内连通性差 | 试用为主 | ~$399-499/月起跳 | 有 | 太贵，国内不可用 |

**推荐：腾讯云 Chat 国际版。** 理由：唯一同时满足"海内外都支持 + 便宜"的选项；家庭群小（≤10 人）、低频，早期大概率停留在免费档内；离线推送支持挂我们现有 APNs 证书；iOS SDK 成熟（TUIKit 可参考但**不直接用其 UI**，见 §6）。

**接入前验证点（Sprint 0 spike，2 天）**：
1. 国内大陆网络下国际版 SDK 的连接/消息延迟实测；
2. 自定义消息（JSON payload）+ 已读回执 + 语音消息在群聊场景的 API 完整性；
3. 离线推送与我们 APNs 证书共存方案（见 §5.4）。
任何一条不过 → 降级方案：国内用腾讯云 IM 国内站、海外用国际站，双 SDKAppID，后端按用户地区分配（成本不变，复杂度 +1）。

### 3.2 账号打通

- IM userId = 我们的 userId（不新造映射表）；
- **UserSig 由我们后端签发**（腾讯提供服务端算法库），有效期 7 天，App 启动/过期时通过 `GET /api/im/credential` 换取；
- 昵称/头像：登录 IM 后由客户端用我们资料同步到 IM Profile（单向：我们 → IM）。

## 4. 群生命周期（与家庭组完全同步，后端驱动）

| 家庭动作（已有接口） | IM 动作（后端 REST API 调服务商，非客户端） |
|---|---|
| 创建家庭组 | 创建 IM 群（群类型：Work/私有群，禁止陌生人申请），**群主 = 家庭 owner** |
| 兑换邀请码入家庭 | 后端把该 userId 拉进群（服务端 API 静默入群，无需对方同意） |
| 踢出成员（owner only） | 同步踢出群 |
| 主动退出家庭 | 同步退群 |
| 解散家庭（owner only，已有二次确认） | 同步解散群 |
| 群主转让 | **本期不做**（家庭 owner 不可转让，保持一致） |

- 群 ID 存 `family_group.imGroupId` 字段；
- 所有群操作**只允许后端发起**（服务商控制台关掉客户端建群/拉人权限），保证家庭表是唯一事实源；
- 兜底：每日 cron 对账（家庭成员表 vs 群成员列表），修复漂移并告警。

## 5. 消息与卡片体系

### 5.1 消息类型

| 类型 | 发送方 | 载体 |
|---|---|---|
| 文字 / 语音 / 图片 / 大表情 | 用户 | IM 原生消息 |
| 系统卡片（下表 6 种） | 我们后端（以"StarLens 官方"系统身份入群发送） | IM 自定义消息，payload 为 JSON |

### 5.2 系统卡片定义

统一 payload 骨架：

```json
{
  "cardType": "help_request | risk_alert | case_share | daily_scam | weekly_report | milestone",
  "eventId": "family_event 表主键，处置回流用",
  "title": "...",
  "summary": "≤3 行",
  "riskLevel": "high | medium | low | none",
  "deepLink": "starlens 内部路由，点卡片体查看详情",
  "actions": { "elder": [единственный按钮], "guardian": [唯一按钮] },
  "quickReplies": ["chips 文案数组，见 §6.3"]
}
```

| 卡片 | 触发 | 老人端唯一按钮 | 子女端唯一按钮 | 备注 |
|---|---|---|---|---|
| **求助卡** help_request | 老人点"问问家人"提交内容 | （自己发的，无按钮） | 「查看并回复」→ 详情页 + chips | AI 初判结果随卡片同发 |
| **播报卡** risk_alert | 成员查询命中高风险且 `shareQueryResults=true` | 「听 AI 讲」（TTS 朗读结论） | 「打电话给{称呼}」（tel: 拉起） | V5 §3.1.1 自动播报的落地形态 |
| **案例卡** case_share | 成员在案例/情报详情点"发给家人" | 「听 AI 讲」 | 「提醒 TA 看」（触发定向推送） | 卡片底部显示已读名单（§5.3） |
| **每日一骗卡** daily_scam | 每日 18:00 定时任务（AI 半自动选品） | 「听 AI 讲」 | 「转发给朋友」（分享卡带二维码） | V5 §3.3 内容化的进群形态 |
| **周报卡** weekly_report | 每周日 19:00 聚合任务 | 无（默认给子女看） | 「查看周报」→ 周报详情页 | 数据全部来自 family_event |
| **里程碑卡** milestone | 守护满 30/100/365 天等 | 「看看」 | 「分享」（海报 + 邀请二维码） | P2 |

**卡片规范（硬约束）**：一张卡片对一种角色**只出现一个按钮**；按钮文案是动词短语；卡片体本身可点（进详情），按钮只承载"该角色此刻最该做的一件事"。

### 5.3 已读回执

- 复用 IM SDK 群消息已读能力，卡片底部渲染"爸爸已查看"/"3 人已读"；
- 案例卡、播报卡的已读状态**回写 family_event**（`readBy` 数组），供周报统计"提醒 X 次、家人查看 Y 次"。

### 5.4 推送边界（防重复通知）

| 通知 | 通道 |
|---|---|
| 群内用户消息、系统卡片的"新消息"提醒 | IM 服务商离线推送（挂我们 APNs 证书，模板："{家庭名}：{摘要}"） |
| 高风险播报的**强提醒**（子女必须看到） | 我们自有 APNs（绕开 IM 的免打扰设置，复用现有通知偏好） |
| 订阅/账号类通知 | 我们自有 APNs（现状不变） |

规则：同一事件**最多一条自有 APNs**；卡片入群产生的 IM 推送与自有强提醒不同时发（高风险播报只发自有强提醒，IM 侧静默入库）。

## 6. 交互设计（老人优先，位置规范）

### 6.1 家庭 Tab = 群聊

- 普通模式：家庭 Tab 进入后直接是群聊页；成员管理/邀请/设置收进右上角「⋯」；
- **长辈模式：家庭 Tab 点开即群聊，无任何中间页**；导航栏只有家庭名 + 返回。

### 6.2 长辈模式聊天页布局（关键交互稿）

```
┌─────────────────────────────┐
│  ← 我们家              ⋯    │  导航栏：仅返回 + 家庭名 + 更多
├─────────────────────────────┤
│                             │
│  [系统卡片：播报卡]          │  卡片宽度 = 屏宽-32pt，圆角 16
│  ┌───────────────────────┐  │
│  │ ⚠️ 高风险提醒          │  │  标题 22pt 加粗
│  │ 您查询的链接 95% 是    │  │  正文 ≥19pt，最多 3 行
│  │ 投资类诈骗…           │  │
│  │ ┌───────────────────┐ │  │
│  │ │   🔊 听 AI 讲      │ │  │  唯一按钮：高 52pt，通栏
│  │ └───────────────────┘ │  │
│  └───────────────────────┘  │
│                             │
│         普通气泡（语音）  🔵 │  语音气泡自动带转文字
│                             │
├─────────────────────────────┤
│ [收到]  [我没点]            │  ← chips 区：紧贴输入区上方，
│                             │     高 44pt，最多 3 个，有待办才出现
├─────────────────────────────┤
│ ┌─────────────────────┐ ⌨️  │
│ │    🎤 按住说话        │     │  语音键通栏占 ~80% 宽、高 56pt
│ └─────────────────────┘     │  键盘图标 44×44 在右侧，点击换文字输入
└─────────────────────────────┘
```

位置规则（长辈模式）：
1. **「按住说话」默认占据输入区主位**（宽 ~80%、高 56pt），文字输入是右侧一个 44×44 的键盘图标，点击后两者互换 —— 完全照抄微信的位置记忆；
2. **chips 固定出现在输入区正上方**（微信小程序键盘快捷条的位置），不悬浮、不遮消息；仅当存在"待处置事件"时出现，点击即发送并消失；
3. 卡片唯一按钮**通栏放在卡片底部**，与卡片边距 12pt，拇指热区 ≥52pt；
4. 长辈模式字号跟随现有 `fontScale`，卡片正文下限 19pt；
5. 「听 AI 讲」用系统 TTS（AVSpeechSynthesizer）朗读卡片 summary + 建议，播放中按钮变「停止」。

### 6.3 快捷回复 chips（普通模式同样有，尺寸略小）

| 场景 | 接收角色 | chips | 点击后 |
|---|---|---|---|
| 求助卡 | 子女 | 「别信❗」「没事✅」「我看看」 | 发一条群消息 + 写 family_event 处置状态（dismissed/confirmed_safe/checking） |
| 播报卡 | 老人 | 「收到」「我没点」 | 发群消息 + 事件标记 acknowledged / not_clicked |
| 案例卡 | 老人 | 「知道了」 | 发群消息 + 已读标记 |

chips 本质是**预设文案的普通消息 + 结构化处置记录**，二者一次点击同时完成 —— 这是周报"处置率"数据的唯一来源，实现时不允许只发消息不落事件。

### 6.4 求助确认闭环（问问家人）

```
老人侧                                    子女侧
─────────                                ─────────
首页长辈模式大按钮「问问家人」
  → 粘贴文字 / 传截图（复用现有输入组件）
  → AI 分析（复用 queryXXX，出初判）
  → 求助卡自动发进家庭群 ──────────────→  自有 APNs 强提醒
                                          → 打开卡片详情（AI 完整分析）
                                          → 点 chips「别信❗」
老人群里收到女儿的「别信❗」 ←──────────  同时事件置 dismissed
  + 卡片状态变「已确认：危险」
```

- 入口位置：长辈模式首页在"拍照识别"旁增加同级大按钮「问问家人」；普通模式在分析结果页增加"问问家人"次级入口；
- 未加入任何家庭的用户点击 → 引导创建/加入家庭（转化入口）。

### 6.5 群管理与表情（P1）

- **群主（=家庭 owner）**：改群名（默认"{owner 昵称}的家"）、移除成员（复用踢出家庭，双确认）；普通成员：仅退出（=退出家庭）；
- **表情**：第一阶段内置一套**大表情**（单个表情作为消息发送时放大显示，微信同款行为），选用开源 emoji 资源；自定义贴纸包放 P2；
- 消息长按菜单：复制 / 举报 / （撤回，仅自己 2 分钟内）—— 长辈模式下菜单项字号同步放大。

## 7. 数据模型

### 7.1 family_event（新表，统计与周报的唯一事实源）

```prisma
model FamilyEvent {
  id           String   @id @default(cuid())
  groupId      String   // 家庭组
  actorUserId  String   // 触发人（老人/分享者）
  cardType     String   // help_request / risk_alert / case_share / daily_scam / weekly_report / milestone
  riskLevel    String?  // high / medium / low / none
  refType      String?  // query / case / intel
  refId        String?  // 关联查询记录或案例 ID
  imMsgId      String?  // 对应 IM 消息 ID（对账/撤回用）
  status       String   @default("open") // open / acknowledged / dismissed / confirmed_safe / checking / not_clicked
  handledBy    String?  // 处置人 userId
  handledAt    DateTime?
  readBy       Json?    // ["userId", ...] 已读回执回写
  payload      Json?    // 卡片快照
  createdAt    DateTime @default(now())

  @@index([groupId, createdAt])
  @@index([groupId, cardType, createdAt])
}
```

### 7.2 已有表变更

- `family_group` + `imGroupId String?`、`imGroupName String?`；
- `user` + `imBlockList Json?`（拉黑名单，双写到 IM 服务商）。

## 8. 接口草案

| 接口 | 说明 |
|---|---|
| `GET /api/im/credential` | 返回 { sdkAppId, userId, userSig, expiresAt }；未入任何家庭也可登录 IM（为后续单聊留口） |
| `POST /api/family/help-request` | 老人求助：{ content/imageUrl } → AI 分析 → 写 family_event → 发求助卡 → 触发强提醒 |
| `POST /api/family/events/:id/handle` | chips 处置：{ action } → 更新 status/handledBy → 由客户端同时发预设群消息 |
| `POST /api/family/share-case` | 案例/情报一键发家庭：{ refType, refId } → 写事件 → 发案例卡 |
| `POST /api/family/events/:id/read` | 已读回写（客户端收到 IM 已读回执后上报，或直接由后端轮询 IM 回执） |
| `POST /api/im/report` | 举报：{ msgId, reason } → 落库 + 邮件告警（复用案例举报的语义） |
| `POST /api/im/block` / `DELETE /api/im/block/:userId` | 拉黑/解除（写自库 + 调服务商黑名单 API） |
| 定时任务 | daily_scam 18:00 选品进群；weekly_report 周日 19:00 聚合进群；im-group 对账 cron |

现有 `POST /broadcast`、`GET /broadcasts`（家庭官方消息）：**冻结不删**，老版本客户端继续可用；新版本客户端不再调用，历史官方消息不迁移（群聊从新开始），下下个版本再评估下线。

## 9. 合规最小集（App Store 1.2 过审清单）

| 要求 | 实现 |
|---|---|
| 举报机制 | 消息长按「举报」+ 卡片详情页举报入口（§8） |
| 拉黑能力 | 成员详情页「屏蔽此人消息」（家庭场景少用，但必须有） |
| 内容过滤 | 服务商内容安全插件**先不开**，保留开关；敏感词基础过滤用服务商自带能力 |
| 违规处置通道 | 举报落库 + admin 后台查看（复用案例举报列表页样式） |
| 审核备注 | App Review 备注里说明：仅限受邀家庭成员的私密小群，无陌生人社交 |

国内：用户已实名（手机号/Apple 登录），举报通道满足处置要求。

## 10. 排期（3 个 Sprint，共约 5 周）

```
Sprint 0（3 天）— 技术验证
└─ 腾讯云 Chat spike（§3.1 三个验证点）+ 建正式应用 + UserSig 服务端签发
```

## 12. 变更记录（2026-07-08 UI 评审后，以下条目覆盖前文冲突处）

1. **老人端 chips 删除**（原 §6.3 播报卡「收到/我没点」、案例卡「知道了」）—— 场景太单一。老人已读改由 IM 已读回执自动上报；老人回应走正常聊天。**子女端 chips 保留**（求助卡「别信❗/没事✅/我看看」，仍然双写群消息 + family_event）。
2. **周报卡 + 周报详情页暂缓**（原 §5.2 / 排期 Sprint 2）—— 发给谁未定（群发有老人自尊问题）。family_event 照常落数据，等灰度后再定形态。"守护可见"暂由已读名单 + 处置横幅 + 防护清单承担。
3. **求助闭环重构**（原 §6.4）：不再单独造流程页。**求助入口 = 每条 AI 分析结果旁的「发到家庭群」按钮**（长辈首页 ElderHomeView 对话流 + 普通模式 HomeContainerView 结果区，复用 ShareToFamilySheet 发送链路）。持续语音/文字输入天然支持（就是既有对话流）；同一 conversationId 重复发送更新原求助卡（去重防刷屏）。底部 Tab 栏全程保留，不做沉浸式。`POST /api/family/help-request` 入参改为 { conversationId/queryId }（携带 AI 结论快照）。
4. **求助卡子女端默认按钮删除**：整卡可点进详情（卡底灰字提示），回应交给 chips 与聊天。播报卡「打电话」、案例卡「提醒 TA 看」保留（动作型按钮不砍）。
5. **成员称呼 = 群昵称，仅群主可设**，设置后全员可见（成员详情页入口）；卡片称呼、回复署名全部取自它，未设置回退用户昵称。family_member 表加 `groupNickname` 字段。
6. **语音转文字：iOS 本地 SFSpeechRecognizer**（离线、免费、隐私不出设备），不用服务商转写。
7. **家庭免费 5 人**：后端 `FREE_MAX_FAMILY_MEMBERS` 3 → 5（付费 10 人不变）；群设置页显示 4/5 并在差 1 人满员时出家庭包升级横幅。**注意兼容**：改动只放宽不收紧，线上老版本文案里写死"3 人"的地方要一并检查。
8. **多家庭**：沿用线上 FamilySwitchSheet 切换（左上角「⇄ 切换」，仅 ≥2 家庭时显示），切换家庭 = 群聊/群设置整体切换；家庭 Tab 角标 = 全家庭未读之和，sheet 内分家庭显示未读数。
9. **群设置页合并线上 ⋯ 菜单全部能力**：分享我的查询结果（shareQueryResults）、通知偏好设置、切换家庭、用邀请码加入、解散/退出 + IM 新增（群名、免打扰、群昵称管理、防护清单入口）。⋯ 菜单只留「群设置、邀请家人」。
10. **长按菜单新增「查一查是不是骗局」**：群里任意消息一键转入 AI 分析 —— 主产品能力埋进聊天的最短路径。
11. UI 原型 v2：docs/V5.1_UI_Mockups.html（S0 家庭 Tab 三态 / S1-S2 群聊双视角 / S3 求助闭环 v2 / S4 卡片全集 / S5 群设置 / S6 防护清单）。
