# AI 分析链路全面复核（2026-10-06）

范围：从 App 发起分析到结果展示的完整链路，包括意图分流、提示词、评分、缓存、风险库、延迟、额度和隐私。
方法：三个独立复核方向并行，均为只读审查，加上把服务端编译到临时目录离线运行纯函数（分类器、评分、解析、提示词拼装）。全程未访问生产库、未调用付费大模型。
标注：【跑过】表示有离线运行结果；【读码】表示仅读代码。最关键的几条已二次抽查确认。

## 总体结论

最可能导致「App 说低风险，用户却被骗了」的有三处，都已离线复现：

1. **评分引擎把大模型的 high 降级**：只要 RAG 命中 1 条，最终分 = AI×0.6 + 少量加分，没有风险库命中时永远到不了 high。
2. **意图分流把诈骗当闲聊，且所有兜底都偏向闲聊**：分类失败或输出看不懂时默认闲聊；带问候语的诈骗短信被判成闲聊；上一轮是闲聊时，短句直接继承成闲聊。闲聊结果只显示纯文字气泡，没有风险卡，也没有「发给家人」。
3. **大模型失败的「无法确定」结果被缓存 90 天、所有人共享**；缓存 key 不含提示词版本，风险库更新后旧结论还会继续返回。

## P3：提示词质量与数据合规

- 提示词要求模型「检查页面内容、域名注册时间、工商登记、投诉记录」，模型根本拿不到这些数据，容易编造「经查询……」。
- 对没见过的 URL 偏向判 low（「若无可疑特征可给 low」），新注册的干净钓鱼域名会显示绿色。low 的定义应该是「未发现信号（不等于安全）」。
- confidence 有两套互相矛盾的定义（和等级绑定 vs 确定程度）。
- 自家域名提示没有覆盖「冒充星识官方」和 `starlensai.com@evil.top` 这种写法。
- 自家邀请短路给出 verdict:'safe'、95 分：骗子也能用真实邀请码拉老人进群。应改成「链接是真的，但只接受认识的家人发来的」；分享到家庭群时标题会显示英文 "safe"。
- 检测输出对老人不够友好：理由和建议没有字数上限；长辈模式标记没有传给后端。
- 「12320 公益心理热线」有误（12320 是卫生热线）；编造的「设置 → 帮助与客服 → 反诈」菜单路径会过时。
- `scamDetectionPrompt` 是死代码，契约和现行版本冲突。
- 豆包调用没有设 temperature、max tokens，也没关推理模式；主备模型的判定稳定性不一致。
- 隐私：每次调用都把完整提示词和用户原文（短信、手机号、卡号）打进 Railway 日志；评测样本 100% 采样、含 userId，注销账号不删除；所有表都没有清理任务。
- 统计：闲聊和知识问答也写进 queries 表（unknown），拉大了「高风险占比」的分母；query 表没记 intent 和 via，误路由无法审计。
- 后台可以改 aiBaseUrl，把全部用户内容转发到任意地址，没有白名单也没有审计日志。

## 建议修复顺序

1. **P0-1/2**：评分改为「以大模型等级为下限，风险库和 RAG 只能加分」；confidence 解析做容错。
2. **P0-3/4/5/6/7**：分流改成「拿不准就检测」。分类失败和输出看不懂一律走检测；继承只升级不降级；寒暄规则只对短句生效；求助层只认第一人称的「已发生」，转述原文先检测；闲聊和知识回答增加 `scam_suspected` 字段，命中则升级为风险卡。
3. **P0-8/9**：按钮白名单（服务端和 iOS 都做）；所有提示词加「禁止输出除官方热线外的任何电话、网址」。
4. **P1-10/11**：失败结果不缓存；缓存 key 加提示词版本；TTL 降到 7 天以内。
5. **P1-12/13**：抽取全部 URL 和电话查库；按域名后缀匹配；多条记录取最高等级。
6. **P2-17/18/19**：分类改用轻量模型、超时 5 秒；主调用超时 45 秒；分析请求不自动重发。
7. 其余按排期处理。

## 提示词宽严校准（2026-10-07）

用户关注「会不会太严」。实测结论：**原提示词对正常内容并不严**（20 句日常话 0 句被标中/高风险），反而对部分典型诈骗偏松（4/20 只给 medium）。本轮改动（PROMPT_VERSION 2026-10-07.v3.2）：
- 框架：用户原文不再预设为「可疑样本」；人设加「如实判断、不为谨慎夸大」。
- medium 门槛：必须有具体动作（要钱 / 要验证码 / 点链接 / 加私聊 / 以异常中奖为由催促）；仅身份不明的普通通知判 low/unknown。
- high 规则：「冒充身份或借口」+「要求转账 / 付费 / 验证码 / 点链接 / 加私聊」⇒ high，不因「无法核实」降级；summary 与等级必须一致。
- 联系方式规则放开「引用原文里的号码和链接」。
- 提问式诈骗（「…能做吗」）仍做检测；服务端兜底 `enforceCardForRisk`：高/中风险不得按闲聊渲染；summary 写「典型诈骗」却只给 medium 的提到 high。
- 豆包请求固定 temperature 0.2（20 条诈骗重跑仅 1 条等级变化）。
- 复核后回退了「summary 写了典型诈骗就提到 high」的正则（对否定句误升、对断言漏判）；兜底翻卡只在首轮生效，追问不翻卡、不扣额度；high 规则改为「点链接后要输入账密 / 付款」才算索取，正规通知带链接无索取 → low；medium 加回「域名仿冒 / 混淆字符」。
- 最终结果（PROMPT_VERSION 2026-10-07.v3.3，lite，t=0.2）：60 条 60/60；正常 28 条（含官方通知带链接 5 条、正规裸 URL 2 条）0 条 medium/high、15 条按闲聊、其余 low；诈骗 27 条 19 high / 8 medium（medium 多为无风险库命中的裸仿冒 URL、以及只要求「联系 / 加微信」未直接要钱的话术）；注入 2/2；解析失败 0；中位 4.5 秒。评测集 scratchpad `cases_v4.json` / `cmp4.js`。
- 仍偏松的 1 条：「妈，我手机掉水里了…先转 3000，加我微信」lite 稳定给 medium 60；可在后续批次用「冒充熟人 + 要钱」确定性规则兜底。
